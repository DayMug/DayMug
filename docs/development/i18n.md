# Internationalization (i18n)

DayMug's UI is fully localized with **vue-i18n**. Two locales ship today:
English (`en`) and Simplified Chinese (`zh`). The backend returns English-only
API errors; the frontend owns all user-facing copy.

## Layout

| Path | Role |
|------|------|
| `frontend/src/i18n/index.ts` | vue-i18n setup, locale detection, `localStorage` persistence (`daymug.lang`) |
| `frontend/src/i18n/locales/en.ts`, `zh.ts` | the translation trees (`export default { ... }`, nested keys) |
| `frontend/src/composables/useLocale.ts` | `locale` / `setLocale` / `toggleLocale` / `t` wrapper |
| `frontend/src/i18n/parity.ts` | shared parity-check logic (no Vite imports — loads under bare `node`) |

Reference keys in components with `t('section.key')` (params: `t('k', { name })`).
Tokens use `{name}` / `{0}` and must appear in **every** locale for a key.

## Adding or changing copy

1. Add the key to **every** locale file (`en.ts` and `zh.ts`) with matching
   `{placeholders}`. Never hardcode a user-visible string in a component.
2. Run `pnpm i18n:check` (or `pnpm test`, which includes `parity.test.ts`).

## Guardrails

Two layers keep coverage complete; both run from the **pre-commit hook** when
the commit touches `frontend/`. (The same hook also runs the Go/TS API contract
check, `scripts/check-api-contract.mjs`, for any `frontend/` or `backend/` change.)

### 1. Deterministic parity — `pnpm i18n:check` (zero tokens)

`frontend/scripts/check-i18n.mjs` imports every locale and fails the commit on:

- a key present in one locale but **missing** in another,
- a **placeholder** set that differs between locales for the same key,
- an **empty** value, or an object-vs-string **shape mismatch**,
- a bare `@` or `|` — vue-i18n reads them as linked-message / plural **syntax**
  and throws a `CompileError` from inside the render function, which unmounts the
  app and leaves a blank page. Write them as `{'@'}` / `{'|'}`. Those escapes are
  literals, not interpolation, so they are excluded from the placeholder compare.

It also prints soft *warnings* for non-reference values byte-identical to English
(likely untranslated); these never block. `--strict` promotes warnings to errors.
The same check also runs in the frontend test suite via `frontend/src/i18n/parity.test.ts`.

### 2. Semantic scan — sonnet sub-agent (opt-in)

`frontend/scripts/i18n-llm-check.mjs` catches what parity cannot: a brand-new
literal sitting in a `.vue`/`.ts` file that should have gone through `t()`. It
feeds **only the staged added lines** to `claude -p --model sonnet` and fails the
commit if the model reports hardcoded user-facing text. Running the cheap model
on a minimal diff keeps a typical commit to a few hundred tokens. Because it
sends the diff to Anthropic and bills the logged-in `claude` account, it runs
only when `DAYMUG_I18N_LLM=1` is set. It skips
silently if the `claude` CLI is absent or a model call fails — it never blocks a
commit on infrastructure flakiness.

### Switches

| Variable / flag | Effect |
|-----------------|--------|
| `DAYMUG_SKIP_I18N=1` | skip the whole hook (both i18n checks **and** the API contract check) |
| `DAYMUG_I18N_LLM=1` | enable the sonnet scan (off by default) |
| `DAYMUG_SKIP_API_CONTRACT=1` | skip only the API contract check |
| `git commit --no-verify` | skip all hooks |

## Installing the hook

Hooks live in `.githooks/` (tracked). Install into your clone with:

```bash
sh .githooks/install.sh
```

It copies `pre-commit` into `.git/hooks/` (backing up a differing existing hook
to `pre-commit.bak`) and is safe to re-run after pulling hook updates.

## Adding a new locale

Drop `frontend/src/i18n/locales/<lang>.ts` (same key tree), register it in
`frontend/src/i18n/index.ts`, and `pnpm i18n:check` will start enforcing it
automatically — the checker discovers every file in the `locales/` directory.
